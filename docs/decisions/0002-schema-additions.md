# 0002 · 사양서에 없는 컬럼을 추가한 이유

상태: 채택 · 2026-08-26

사양서 §4-2 의 테이블 정의에 아래를 더했다. 전부 "없으면 나중에 복구 불가능한
정보"이거나 "판정 지표를 자동 산출하는 데 필요한 값"이다.

## training.requests

| 추가 | 이유 |
|---|---|
| `explored boolean` | §5-1 4단계 탐색 당첨으로 **강제** 외부 라우팅된 호출. 이 표시가 없으면 §6-1 승격 판정 통계가 탐색 트래픽에 오염된다. 사후 복구 불가. |
| `routing_reason text` | 어떤 규칙이 이 라우팅을 만들었는지. 비용이 튀었을 때 원인을 사후에 찾을 유일한 단서. |
| `fallback_from text` | 제공자 장애로 강등된 사실. 이게 없으면 "왜 이 유형이 갑자기 외부로 갔는가"에 답할 수 없다. |
| `status` / `error_code` | requests 는 제공자 호출 **전에** 삽입된다(§5-1 2단계). 완결 여부를 구분하지 않으면 §10 4주차 지표("100% 기록")가 무의미해진다. |
| `api_key_id` | 인증 주체 추적. |

## training.models (신규 테이블)

사양서에 없는 테이블이다. 대신 이것이 없으면 §2-1·§2-2·§11 을 강제할 지점이 없다.

- 어떤 모델의 출력이 학습에 들어갈 수 있는가 (`training_safe`)
- 라이선스 원문을 확인했는가 (`license_verified_at`)
- 단가가 실측인가 추정인가 (`pricing_verified_at`)

이 셋을 코드에 하드코딩하면 §2-1 이 요구하는 "사람 규율 아닌 권한 차단"이 아니라
그냥 규율이 된다.

## training.gateway_config (신규 테이블)

§5-3 은 "상한은 설정값으로 노출하되 기본값 75% 초과 불가"를 요구한다.
환경변수만으로는 "초과 불가"를 강제할 수 없다. DB CHECK 로 고정하고,
환경변수는 이를 **조일 수만** 있게 했다.

`route_unclassified_to_external` 스위치도 여기 있다. §5-2 의
"task_type=unclassified → 외부 고성능" 규칙을 2주차에 켜면 아직 분류기가 없으므로
**전 트래픽이 외부로 간다**. §8 2주차는 "기본 라우팅(입력 길이 기준만)"을 지시하므로
이 스위치는 3주차 분류기 도입 시점에 켠다.

## training.api_keys (신규 테이블)

§5-1 1단계 "인증 확인"의 구현체. 원문 키는 저장하지 않고 sha256 해시만 둔다.

## 사양서에 있으나 아직 만들지 않은 것

`shadow_runs`, `model_versions`, `training_snapshots`, `reference.documents`,
`reference.doc_chunks` 는 §8 상 3주차 이후 산출물이다. §12 게이트가 열리기 전에
만들면 쓰이지 않는 스키마가 먼저 굳는다.
